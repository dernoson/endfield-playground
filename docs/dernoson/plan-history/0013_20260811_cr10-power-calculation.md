## 主題簡述

CR-10 產線電力計算 —— 依供電樁佈局計算設備供電範圍與整區耗電量，並偵測未供電與超載兩種問題。計算結果供 CR-04 產線總覽面板顯示電力狀態。

規格出處 `spec/10_power_calculation.md`（v0.3）。計算部分屬 Phase 1，兩個 Warning 屬 Phase 2。

**本計畫的約束**

- `spec/` 是對外文件，統籌決斷寫在本計畫，不寫回 `spec/`。
- `待實作` 代表「規格已定、尚未逐項對照程式碼確認」；`PowerSummary.vue` 已存在（見 O1），動任一格前先核對現況。
- 顯示規格明文沿用 CR-03 的定義，本 CR 只提供警示內容，不另立一套 UI。
- 基地模式下不允許擺放中繼器，供電覆蓋僅由供電樁決定 —— 不要為中繼器保留計算路徑。

## 規劃描述

依 spec 主要章節切格：觸發時機、供電範圍判定、耗電量加總、總供電量設定、W004、W005、面板呈現，最後以驗證表格收斂。

「供電判定」與「耗電量加總」分開成格，因為兩者的失敗方式不同：前者錯會讓設備該亮不亮（部分重疊算不算供電成功），後者錯會讓總量對不上（未供電設備的耗電量有沒有被排除）。spec 的驗證表也是分開列的。

「總供電量由使用者自訂、未設定視為無限」獨立成格：它是 W005 是否觸發的前提開關，且「未設定時無論耗電多高都不觸發」本身就是一項驗證。

## 觀察與推論

### O1 · 2026-08-11 03:25:00+08:00 — 電力側既有實作盤點

`src/components/StatsPanel/PowerSummary.vue` 對應總覽面板的電力區塊；`src/data/machines.ts` 應持有各設備耗電量與供電樁範圍定義；`src/utils/geometryUtils.ts` 與 `src/utils/shirone/getMachineOccupiedGrids.ts` 提供佔格計算，供電範圍聯集判定可以建立在同一組幾何工具上。`src/lib/validation/detectors/` 下沒有電力相關 detector。

呈現層先於計算層存在，與 CR-09 的情況相同。供電範圍判定本質上是「設備佔用格子與供電樁範圍聯集是否有交集」，與 CR-03 的重疊偵測是同一類幾何問題，應復用 `getMachineOccupiedGrids` 而非另寫一套佔格邏輯。

### O2 · 2026-08-11 03:30:00+08:00 — 供電狀態同時影響流量估算但 spec 未言明

spec 2.2 節寫「設備須部分處於供電樁範圍內才會運作，並耗用該設備設定的耗電量；完全處於範圍外的設備不耗電、不運作」。但 W004（設備未供電）是 Warning，而 `spec/04_flow_simulation.md` 2.2 節只說「有 Error 等級警示的設備與管線略過計算」。

於是有一個 spec 沒回答的問題：未供電的設備「不運作」，那它在流量估算中應該輸出 0、還是照常估算？照 CR-04 的規則它不是 Error，不會被略過，會被當成正常運作的設備算出流量 —— 這與「不運作」矛盾。留待實作階段撞到時回報使用者裁決，不在此逕自選邊。

### O3 · 2026-08-11 04:50:00+08:00 — 供電範圍在資料層根本不存在，現有耗電加總在規格上是錯的

`Machine` 介面（`types/machine.ts:110`）只有 `power`（正 = 耗電、負 = 產電、-1 = 未定義），**沒有任何供電範圍欄位**。`machines.ts` 中「供電樁」與「息壤供電樁」是 2×2、`power: 0`，沒有 N×N 覆蓋範圍；「中繼器」與「息壤中繼器」是 3×3，同樣沒有範圍。所以 0013#2 缺的不只是演算法，是資料 —— 供電樁能罩多大在程式碼裡查不到。

耗電加總：`runFlowEngine`（:1379）以 `totalPowerDemand = Σ def.power`（所有 `isValid` 且 `power > 0` 的節點）計算，**完全不看供電覆蓋**。規格要求未供電設備不計入，所以這個數字目前在規格上是錯的，不是「部分完成」。

總供電量：`runFlowEngine` 寫死 `totalPowerSupply: 0`，`flowStore` 也沒有讓使用者設定的入口。連帶 `powerBalance = 0 - demand` 恆為負，`ProductionStats` 的電力狀態只要畫布上有耗電設備就永遠顯示「不足」。

`src/lib/validation/detectors/` 下沒有電力 detector，W004 / W005 都不存在。

順帶一提：中繼器有兩台（中繼器、息壤中繼器）而非一台，兩台都掛在「電力」tag 下 —— 0014#5 的隱藏規則要涵蓋兩台。

### 2 供電範圍聯集與供電判定

- **state:** 待實作
- **basis:** → O3

供電樁具有 N×N 方形供電範圍，大小由設備定義決定。取所有已擺放供電樁的供電範圍聯集；設備**任一格**落在聯集內即視為供電成功。基地模式下不允許擺放中繼器，供電覆蓋僅由供電樁決定。

前置是補資料而非寫演算法：`Machine` 沒有供電範圍欄位，兩台供電樁在 `machines.ts` 中只有 2×2 的佔格與 `power: 0`（O3）。要先決定範圍值從哪來（`docs/aaaaa/data/machines.json` 加欄位並重跑 `pnpm generate:src-data`）再談判定。

「部分重疊即算供電成功」是關鍵判準，容易被實作成「須完全覆蓋」。應復用 `getMachineOccupiedGrids` 取得設備佔格（O1），不另寫佔格邏輯。

判準：spec 第 3 節「部分重疊視為供電成功」「W004 供電覆蓋聯集」兩項通過。

- **state:** 待實作
