## 主題簡述

CR-09 產線流量計算 - 配方警示 —— 監聽畫布狀態與設備配方設定，偵測配方輸入輸出與管線流量相關的問題，分 Error（E004 / E005）與 Warning（W001 / W002 / W003）兩級。有 Error 的節點被 CR-04 略過估算。

規格出處 `spec/09_recipe_warning.md`（v0.3）。Error 屬 Phase 1，Warning 屬 Phase 2。

**本計畫的約束**

- `spec/` 是對外文件，統籌決斷寫在本計畫，不寫回 `spec/`。
- `待實作` 代表「規格已定、尚未逐項對照程式碼確認」；`validationStore.ts` 等已存在（見 O1），動任一格前先核對現況。
- 顯示規格（畫布樣式、面板呈現、點選導覽）明文沿用 CR-03 的定義，本 CR 只提供警示內容，不另立一套 UI。

## 規劃描述

依警示代碼與呈現面切格：觸發時機、E004、E005、W001、W002 / W003、畫布視覺、面板呈現，最後以驗證表格收斂。

E004 與 E005 分開成格而非合成「輸入輸出缺失」一格：兩者的判定資料來源不同（一個看輸入接口有沒有管線連入、一個看輸出接口有沒有管線接出），有各自的驗證項，且 CR-02 的管線刪除只會觸發其中一邊。

W002 與 W003 合成一格：兩者都依賴 CR-04 的流量估算結果、都屬 Phase 2、都是「端點缺失時流量視為 0」的同一條規則的兩個方向，分開會製造兩份幾乎相同的正文。

## 觀察與推論

### O1 · 2026-08-11 03:25:00+08:00 — 驗證側既有實作盤點

`src/store/validationStore.ts`、`src/composables/useValidation.ts`、`src/types/validation.ts` 對應驗證狀態；`src/lib/validation/detectors/` 下目前只有 `overlapDetector.ts`（CR-03 的空間重疊），沒有配方相關的 detector。

所以 CR-09 的偵測器尚未建立，但承載它的 store 與型別已就位。`detectors/` 這個目錄結構本身就是規劃好要放多個偵測器的，本 CR 應照同一模式新增檔案，而不是把配方判定塞進 `overlapDetector.ts` 或 store。

### O2 · 2026-08-11 03:30:00+08:00 — 本 CR 與 CR-04 互為對方的輸入

CR-09 的 E004 / E005 決定 CR-04 略過哪些節點（`spec/09_recipe_warning.md` 2.2 節「有 Error 的設備或管線會被 CR-04 流量估算略過」），而 CR-09 的 W002 / W003 又需要 CR-04 的估算結果才能判斷（2.2 節「管線輸入端流量不足以滿足下游所需」）。

兩者不是單向依賴而是有先後分層的循環：Error 判定必須在估算之前、只看拓撲與配方定義；Warning 判定必須在估算之後、要看流量數值。實作時若把五個代碼放進同一個 pass，會得到「要先有流量才能算警示，但要先有警示才能算流量」的死結。這個分層是本 CR 最容易做錯的地方。

### O3 · 2026-08-11 04:45:00+08:00 — 五個代碼都沒有 detector，但其中三個的判定已經活在 FlowEngine 裡

`src/lib/validation/detectors/` 下只有 `overlapDetector.ts`，沒有任何配方相關 detector，`validationStore.alerts` 恆為空。

但等價的判定已經存在於 `useFlowEngine.ts`，只是以另一種形式：`validateChains`（:443）以 sink 為起點反向 BFS，連不到 sink 的節點與孤立節點標為非法（涵蓋 E005 的部分語意）；`matchRecipeByInputs`（:95）在實際輸入集合對不上任何配方時匹配失敗（W001 的語意）；`markPortCardinalityViolations`（:382）檢查同一埠被多條邊佔用；`detectCongestion`（:1187）算出 `isCongested` 的邊（W003 的語意）。

差別在輸出：這些判定的結果只寫進 `flowStore` 的 `invalidChainUids` / `congestedEdges`，不產生 `Alert`、沒有代碼、沒有訊息、面板與畫布也沒有對應呈現。

所以現況是 O2 擔心的另一端：五個代碼的判定不是被做成單一 pass 才出問題 —— 而是它們現在**全部**擠在 FlowEngine 這一個 pass 裡，並以「算不出流量」代替「產出警示」。CR-09 開工的第一個決定因此是結構性的：把這些判定抽成 detector，還是讓 FlowEngine 也產出 Alert。前者合乎 `detectors/` 的既有結構，但 W002 / W003 本來就要在估算之後，抽出去仍得回頭讀 `flowStore`。
