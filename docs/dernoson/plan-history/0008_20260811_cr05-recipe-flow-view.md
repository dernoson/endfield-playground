## 主題簡述

CR-05 配方流程設計（Flow Chart 視角）—— 讓使用者在抽象的「產物流向圖」與具體的「佈局視角設備配置」之間自由切換，兩者共用同一份產線資料，並可在流程視角做高層次配方規劃後一鍵轉為佈局視角的設備配置。spec 稱它為模擬器的核心賣點之一。

規格出處 `spec/05_recipe_flow.md`（v0.3）。Phase 1 只有佈局 / 流程二態切換與基礎 Flow Chart；並列視角與所有編輯功能屬 Phase 2。

**本計畫的約束**

- `spec/` 是對外文件，統籌決斷寫在本計畫，不寫回 `spec/`。
- `待實作` 代表「規格已定、尚未逐項對照程式碼確認」；`src/components/FlowChart/` 下六個節點元件已存在（見 O1），動任一格前先核對現況。
- Phase 1 不存在並列視角。凡標 Phase 2 的格子不得計入 Phase 1 收斂判準。

## 規劃描述

依 spec 主要章節切格：視角模式與切換控項、資料共用、Flow Chart 節點 / 邊 / 佈局、並列視角的三個面向（版型、點選導覽、編輯聯動）、Phase 2 的三個編輯功能（新增流程配方、切換視角以導入、中間產物選擇），最後以驗證表格收斂。

並列視角拆成三格而非一格，因為 spec 的驗證表把它拆成六項（左右並排、上下切換、比例調整、點選導覽、編輯聯動）分屬不同面向，且版型可以先做、聯動可以後做。

Flow Chart 元件屬 L3（純展示，禁止 import store），視角切換與資料映射屬 L2 —— 這條分界在本 CR 特別容易被違反，因為節點要顯示效率而效率來自 store。

## 觀察與推論

### O1 · 2026-08-11 03:25:00+08:00 — Flow Chart 側既有實作盤點

`src/components/FlowChart/` 下有 Index.vue、DeviceNode.vue、FlowEdge.vue、MaterialNode.vue、ProductNode.vue、WarehouseNode.vue、PendingImportNode.vue 共七個檔案；`src/editor/canvas/FlowNodeOverlay.vue` 疑似對應佈局側的流程疊加；`src/store/editorStore.ts` 可能持有視角狀態；`src/components/StatsPanel/WarehouseEstimate.vue` 對應倉庫直取的估算。

spec 4.3 節列出五種節點樣式（原料、設備、產物、倉庫、待導入），tree 中的六個節點元件正好對得上（MaterialNode = 原料、PendingImportNode = 待導入）。`WarehouseNode` 與 `PendingImportNode` 都是 spec 標為 Phase 2 的東西卻已存在，代表 Phase 2 的部分內容早於排序落地，逐格核對時不能假設 Phase 2 一律未開始。

### O2 · 2026-08-11 03:30:00+08:00 — Tab 鍵在本 CR 與其他 CR 沒有衝突但輪替數隨 Phase 變

spec 4.1 節：視角切換控項位於編輯區左下角，按 `Tab` 鍵輪替。Phase 1 為二態（佈局 → 流程 → 佈局），Phase 2 起為三態（佈局 → 流程 → 並列 → 佈局）。`spec/01_canvas_and_devices.md` 4.3 節的 16 組快捷鍵與 `spec/02_pipeline.md` 4.3 節的 4 組都沒有用到 `Tab`。

所以鍵位本身無衝突，但輪替序列的長度會隨 Phase 改變，且 spec 各有一條專屬驗證項（Phase 1 連按兩次、Phase 2 連按三次）。實作時輪替序列必須由「當前可用視角清單」導出而非寫死，否則 Phase 2 上線要改兩處。

### O3 · 2026-08-11 04:35:00+08:00 — Flow Chart 是一組自帶假資料的孤立示範，且從未被掛上畫面

`src/components/FlowChart/Index.vue` 自己 `ref` 了五個寫死節點（鐵礦砂 / 電弧爐 / 鐵錠 / 主要倉庫 / 高爐）與兩條邊，不 import 任何 store，並實作了「點節點高亮相連邊、點空白處取消」的聯動。五個節點元件與 `FlowEdge` 只被它使用。

但 `FlowChart/Index.vue` 在 `src/` 內零引用：`router/index.ts` 只有 `/` → `MainLayout` 與五條 `/dev` 路由，`MainLayout` 也沒掛它。整組元件目前跑不到任何地方。

也沒有找到視角模式本身：`editorStore` 沒有 viewMode 之類的狀態，沒有 `Tab` 鍵綁定，沒有左下角切換控項，沒有把 `editorStore.nodes` / `flowStore` 映射成 Flow Chart 節點的 L2 層。

所以 CR-05 是 L3 先行、L2 缺席：節點與邊的外殼有了，但沒有真實資料流進去，「節點正確呈現」「邊上流量顯示」都還不成立；而 0008#2（三視角共用同一份 store）恰恰是缺的那一塊 —— `Index.vue` 自帶 mock 資料正是它的反面。

### O4 · 2026-08-11 04:35:30+08:00 — 效率顏色已經分裂成兩份且門檻不同

`src/utils/flowHelpers.ts` 的 `getEfficiencyBg()` 是 Flow Chart 的 `DeviceNode` 在用的效率配色：`>= 1` 綠、`>= 0.75` 黃、`> 0` 橘、其餘灰。佈局側 `FlowNodeOverlay.efficiencyColorClass` 則是 `>= 1` 綠、`>= 0.5` 黃、`> 0` 橘、其餘灰。

spec 定義的是 50–99% 黃，所以 Flow Chart 那份的門檻是錯的：效率 60% 的設備在佈局視角是黃色、在流程視角是橘色。

O2 擔心的「兩套並行的顏色語意」還沒發生，先發生的是同一套語意有兩份實作且已經不一致。這是 0007#8 要求單一來源的實證理由 —— 不是潔癖，是已經漂了。

### 3 Flow Chart 節點類型

- **state:** 實作中
- **basis:** → O3

四種節點：原料節點（產線輸入來源，礦機採集或倉庫直取，顯示供給速率）、設備節點（顯示設備名稱、當前配方、效率）、產物節點（中間或最終產物，顯示當前產出速率）、倉庫節點（標示該品項從倉庫直接取用，不經產線生產）。

樣式規格：原料為圓角矩形深灰背景白字、設備為矩形依效率上色並顯示設備圖示、產物為橢圓帶品項圖示 + 名稱 + 速率、倉庫為橢圓帶倉庫圖示與虛線邊框、待導入為虛線邊框半透明矩形。

五個元件都已存在且各自實作了對應樣式（倉庫為虛線邊框橢圓、待導入為虛線半透明），但只吃 `Index.vue` 的假資料、也沒被掛上任何畫面（O3），所以兩項驗證都還沒真的可測。
