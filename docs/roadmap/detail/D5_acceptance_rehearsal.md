## 1. 背景與動機

「初步串通、可運行」如果沒有一份逐步劇本，就會在 11/29 當天變成各說各話：有人覺得能放設備就算串通，有人覺得要能匯出才算。主編已在 ROADMAP §5 給出 8 步劇本，本項把它固定為**可執行、可勾選、可在會前自己跑一遍**的形式，並排一次彩排。

彩排排在 11/22 而不是 11/28，是刻意的：留一週修補時間。歷史經驗顯示這類串通演示的失敗多半不是功能沒做，而是資料對不上（缺 `machineType`、缺 handle、缺源素材），這類問題發現後通常一到兩天內可修，但必須先發現。

### 4.2 演示產線的選定

**凍結內容（2026-11-28 核定，同日實操）：** 機器 `Machine.id`、順序、材料、配方、管線走向，以及附錄 A 的座標與旋轉。之後不再改。換產線或改座標視為改版本號。

| 順序 | 角色 | `Machine.id`（中文名） | 資料層核定（`src/data/machines.ts`、`products.ts`） |
|------|------|------------------------|---------------------------------------------------|
| 1 | 源 | `material_source`（基礎材料輸出點） | 1×3；`is_source: true`；模式 `solid_belt`，輸出口在**右側**（right, offset 1, belt）。可選材料含固體 **源礦**（`sourceMaterialOptions` 依 belt 過濾）。速率預設 30/min |
| 2 | 加工 | `crusher`（粉碎機） | 3×3；輸入在**頂部** 3 格（belt），輸出在**底部** 3 格（belt）。配方 `crusher_yuan_ore_powder_0`：源礦 ×1 → 源石粉末 ×1，2 秒，`machineMode: default`，`environment: none`。單入單出，兩機速率皆 30/min |
| 3 | 匯出點 | `item_sink`（物品輸入口） | 1×3；`is_sink: true`；輸入在**右側** belt。引擎以 `sinkDeliveries` 計入匯出 |

**管線走向：**

- 源（右側出口）→ 加工機（頂部入口）：源的出口在右、加工機的入口在頂，兩者刻意錯開一格，接線至少一個 90 度彎。
- 加工機（底部出口）→ 匯出點（右側入口）：實操結果見附錄 A 管線 B，先下再左，一個彎。

**為何選這組：** 源礦是固體，走 belt，不引入 pipe 變數；配方單入單出，不需多輸入；粉碎機吃 30/min、出 30/min，與源和 belt 上限一致，右側數字不會因速率錯配而看不懂。

**核定方式：** 資料層（機器埠位、配方、可選材料、引擎匯出點判斷）已核。2026-11-28 在正式頁 `/` 照這組擺過一次，三台與兩條管線都接得上，座標見附錄 A。若 11/29 這組接不通，不換產線，把該步記為未過並寫原因。

**選定條件（沿用）：**

| 要求 | 說明 |
|------|------|
| 節點數 | 3 台（源 → 加工 → 匯出點），不多不少 |
| 材料 | 固體（belt），避免 pipe 相關的額外變數 |
| 配方 | 單一輸入單一輸出，不用多輸入配方 |
| 彎折 | 兩台設備刻意錯開一格，強制產生一個 90 度彎 |

**產線一經選定即凍結**，寫進本檔附錄，所有彩排與正式演示用同一組。這讓「上次可以這次不行」變成可追查的回歸問題。

### 4.3 不開 `/dev` 的理由

驗收劇本明確要求不開 `/dev` 頁。`/dev` 是 L1 的除錯工具，能在那裡跑通只證明引擎正確，不證明主線串通——而串通正是本輪的唯一目標。`/dev` 保留為**除錯備援**：演示失敗時用它區分「引擎錯」還是「接線錯」。

由非開發者操作是關鍵：寫程式的人會下意識避開已知的坑。
