# W1004-T1 步驟 04：框線、Error 與手動驗收

狀態：未執行。前置：[步驟 03](./W1004-T1_step_03_base_data.md) 完成。

## 目標與修改檔案

修改 `GridCanvas.vue` 的基地框與設備標記，同步 `GridCanvas.stories.ts`。正式頁驗證視窗、出界與落子互相一致。LayoutView 只做資料映射，不承擔設備填色與字重設計。

## 執行順序

1. 基地尺寸非 null 時，在世界座標 `(0,0)` 畫寬 w、高 h 的矩形，轉成相同 cellSize 尺度。框線套用同一視窗 transform，使用無填色 overlay；不要讓矩形填滿遮住設備或攔截事件。
2. 每台設備建立穩定群組或其他可定位標記，使用 `data-device-id`；跨 z 的同一 xy 格維持目前只畫一次的行為。
3. 出界設備加 out-of-base class／對應狀態 prop，並提供最低限度可看見的 Error 邊框或提示。應能辨識是哪台設備出界，不只改一個無可見樣式的 class。
4. 保留設備名稱、管線和設備原有佔格。正式設備填色、字重與完整視覺稿留給 G＋S，不順便重做整張畫布。
5. Story 提供明確容器寬高，覆蓋預設、空資料、自由畫布、基地內、部分跨界、多台出界及平移後狀態；不用 Pinia。若 Story 的事件接線影響使用性，同步提供可操作的視窗包裝。
6. 執行 pnpm dev，在正式首頁透過真機器工具列驗收。基地選擇使用現有 Navbar，不新增另一組基地控制。

## 正式頁手動案例

| 編號 | 操作                                    | 預期與證據                                                     |
| ---- | --------------------------------------- | -------------------------------------------------------------- |
| M01  | 自由畫布平移，在 x≥12 或 y≥8 的空格落子 | 設備可見；記錄實際格座標與設備 ID                              |
| M02  | 自由畫布平移到負座標落子                | 可放置，無基地 Error                                           |
| M03  | 選武陵，在原點附近觀察框線              | 框線可見；資料尺寸為 256×256；視窗只顯示其中可見部分是正常現象 |
| M04  | 在負座標，或平移至武陵遠端框外落子      | 放置成功且該設備有 Error；不要求整個基地同時裝進視窗           |
| M05  | 放置原點在內、部分佔格越界的多格設備    | 整台設備標示出界                                               |
| M06  | 切四號谷地，觀察落在兩基地差異區的設備  | 依 192×192 更新 Error                                          |
| M07  | 取消基地                                | 框與出界 Error 清除，設備資料保留                              |
| M08  | 拖曳平移後放開，再正常左鍵落子          | 拖曳不落子，後續點擊正常                                       |
| M09  | 點子元素、改容器大小                    | 點擊與實際格線對齊；設備、框與管線共同移動                     |
| M10  | 在重疊位置落子                          | 不新增設備，維持原有拒絕                                       |
| M11  | 對成功落下的出界設備 undo／redo         | 資料與 Error 同步消失／恢復                                    |

旋轉邊界案例可由 Story／既有測試資料提供，不為了驗收新增旋轉互動。空資料情境使用 Story，正式首頁自動載入 fixture 保持原狀。

檢查 Story Controls、邊界狀態及 Accessibility；確認設備 Error 不只靠顏色辨認。若實際瀏覽器驗收不可用，必須標明待人工確認，不能以 build 成功代替互動結果。

每案記錄通過／失敗／未執行、瀏覽器、操作座標與必要截圖或 DOM 證據。下一步：[步驟 05](./W1004-T1_step_05_quality_gate.md)。
