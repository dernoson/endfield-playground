**對 9 月的啟示（比本週的處置更重要）：在佈局渲染層落地前，不要把任何門檻必要項押在 L2。** 列為 §4 待裁決第 3 項。

性質上是「**重寫 L2 渲染層 ＋ 換 L1 資料模型**」，不是介面調整。

### 2.2 關鍵路徑寬度 ＝ 1（為何加人不會變快）

| 約束 | 後果 |
|------|------|
| 新增的 L1 六個純函式**互相依賴**：`layout.ts` → `deviceOccupancy` → `pipelineGeometry` → `resolveConnections` → `toTopology` | 不能分給六個人，只能一條線走完 |
| `editorStore` 是**唯一寫入點**（ROADMAP §1.2 已定案），八個 action 必須同時改簽章 | 拆成多個 PR 會型別不通、測試全紅；只能一個 PR |
| L2／L3 新元件全部依賴上述兩者的型別 | 前置未完成前，L2／L3 無法開工，只能空等 |

**工作量確實變多，但增加的量集中在一條無法平行的前置路徑上。** 在這條路徑完成前投入額外人力，效益為零；若額外的人去動 `editorStore`，效益為負（撞車）。

加人**有效**的時間點是前置落地之後的 L2／L3 切片階段（`GridCanvas`、四個 L3 元件、五個 composable 可平行），對應 9 月中起。
